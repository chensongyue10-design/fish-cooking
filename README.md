## 一句话介绍

Fish Cooking 是一个面向内容创作者和一人公司的内容再加工 Skill：它会把一份访谈、播客、课程稿、复盘或长文章，整理成适合不同平台阅读和发布的内容。

它不是简单地把同一篇文章改几个标题，而是先提取原稿中的判断、故事、方法和证据，再根据平台场景重新组织表达。

## 它能做什么

一份源材料，默认可以拆成：

- 公众号：完整的方法论、业务判断或深度文章
- 小红书：有明确立场、适合讨论和收藏的短内容
- 朋友圈：带有场景、感受或轻观点的短文案
- 知识星球：一个可理解、可应用的知识单元
- 口播稿：适合连续表达的观点、故事与方法

## 核心工作流

```text
读取原稿
  → 建立事实与证据清单
  → 提炼可独立成立的内容单元
  → 匹配平台与读者动作
  → 先给出选题计划
  → 按用户选择分批生成
  → 检查事实、归属、平台格式与重复度
```

## 核心特点

- **先读素材，再做规划**
- **保留原作者判断**
- **针对不同平台重新组织表达**
- **先选题，后写全文**
- **控制内容重复，不无限生成变体**
- **不擅自补充场景、数字、结果、案例或引用**

## 适合谁

适合拥有访谈、播客、课程、直播、复盘、文章或知识笔记，希望把一份内容持续分发到多个平台的创作者、个人品牌和一人公司。

## 使用方式

在支持 Codex Skill 的环境中，将本仓库作为 `fish-cooking` Skill 使用：

```text
使用 $fish-cooking，把这份访谈先拆成公众号、小红书和口播稿的选题计划。
```

Skill 会先读取材料，给出平台化选题；确认方向后，再生成对应内容。

## 仓库结构

## 设计原则

内容可以被重新组织，但不能脱离证据；平台可以改变表达方式，但不能改变原作者真正说过的话。
